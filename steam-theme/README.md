# Adwaita Steam game pages

Ports the approved Desktop-2026-10-14.2 game-page design with the user-selected rounded Adwaita Play button into native Linux Steam while retaining the surrounding Adwaita theme. Lumen remains the LuaTools loader. Millennium is not required.

Run `python3 install.py` as your desktop user with Node.js 22 or newer available. Restart Steam after installation. The user service waits for Steam's existing loopback debugging endpoint, applies the page assets, reconstructs the CSS-module names used by the approved design, and positions Lumen's button outside Adwaita's clipped menu. The installed client's class map is refreshed whenever the bridge attaches to a new Steam window. Late-loading Adwaita styles are reconciled, including nested rules that suppress Steam's floating bar. Lumen settings use Adwaita surfaces and typography; its fixes control and the floating utility row retain separate hit targets.

The metadata bridge permits only three read-only Steam Store endpoints. It sends no account cookies or credentials and enforces URL, response-size, concurrency and request limits. Non-Steam games are matched only when the normalized title has exactly one Steam result. The info panel starts collapsed.

Game Mode uses Steam Prime v0.2.0 under `~/homebrew/themes`, including its bundled components, fonts, licenses, and all 16 Windows settings. The default CSS Loader profile selects Steam Prime. Desktop-window injection targets are excluded to preserve Adwaita. The existing user service also supplies semantic class aliases to Big Picture and its menu popups, resolving them from the installed Steam build; CSS Loader continues to load the theme CSS. The companion runtime also ports the Windows footer feather, floating-bar state, artwork accents, menu measurements, and interaction/entrance animations. Semantic attribute selectors are indexed in CSSOM after loader translation to preserve their intended targets. Linux’s main-menu browser is kept to the panel width, with the fade drawn in its host to avoid an opaque native popup masking the gradient. Existing Prime settings survive reinstall. Controller behavior requires verification in an actual Game Mode session.

After CSS Loader successfully loads Prime, redundant standalone theme directories can be archived outside `~/homebrew/themes` and removed. Retain any external dependencies declared by Prime; this version has none. Keep CSS Loader runtime files such as `STORE` and `css_translations.json`. Do not delete the loader or its plugins.

To disable the desktop port: `systemctl --user disable --now loew-steam-theme.service`, then restart Steam. Backups of earlier local files and replaced Game Mode themes are stored under `~/.local/state/loew-steam-theme/`. Restore those separately if needed. The bridge does not change game data or Steam credentials.

Reference export SHA256: `652415de58921be62852d34bf7683fa4e0851e6df0a0f4493986165f4fcc5019`. All 130 files in its snapshot manifest were verified before selecting the game-page assets. Upstream Adwaita retains its own license and installation.

The bridge decorates only page changes and image loads. It caches reconciled stylesheets, avoids style-observer feedback loops, and fetches metadata only for the active non-Steam page. Hero logo centering is handled by the page CSS rather than scanning and rewriting the library.

Desktop and Game Mode share an artwork cache that preserves original bytes, stores versioned custom artwork and hash-addressed local Steam heroes/logos in IndexedDB, and warms a bounded set of decoded images during idle time. It does not resize the displayed artwork. The first visit can still require a download/decode; later visits can reuse cached blobs. The cache limits encoded images to 128 MiB in memory and 192 MiB on disk, with at most 96 MiB of warmed decoded images.

The bridge indexes installed user artwork files and supplies exact existing image variants to Steam's custom-artwork lookup. This makes newly imported Windows artwork available on subsequent page visits without restarting Steam and avoids probing missing JPG/PNG alternatives. Native artwork changes made after the index scan fall back to Steam's own lookup. Imported binaries and backups stay in the user's Steam/state folders; they are not bundled in this repository.

Cached heroes and logos are selected through Steam's asset-source getters before image elements mount. The runtime does not rewrite an in-flight image's `src`. The bounded memory cache rotates older inactive entries instead of refusing new images once full, and unready/failed heroes leave the native blurred placeholder visible during fallback.

Desktop heroes fade in with opacity after decode; logos retain the Game Mode scale entrance. Accent changes fade over 440 ms, with reduced-motion support. Play labels use semibold weight. The class compatibility layer batches missing aliases per element. Dark Play lettering uses a 10% text shadow, while light lettering retains 55%.

The neutral palette uses `#202020` for main content, `#292929` for sidebars (sampled from rtxForge's main area), `#2f2f2f` for headers, and `#303030` for opaque GTK cards. Steam's translucent cards retain their glass treatment. `python3 system-palette/install.py` separately opts the desktop user into matching GTK 3, GTK 4/libadwaita and GNOME Shell surfaces, preserving managed accent colours and existing CSS outside its marked block. It copies the installed GNOME dark stylesheet and neutralizes only near-neutral colours, retaining native layout and accent states. Backups, including the previous shell theme name, are written to `~/.local/state/loew-lumen-palette/`. Some running applications require reopening to adopt the palette.

`python3 backport-windows-motion.py /path/to/installed/steam-prime` applies only the desktop hero/logo entrance and accent arrival animations to an existing Windows Steam Prime theme. It preserves the Windows accent resolver and layout and backs up changed files with a hash manifest under `~/.local/state/loew-steam-theme/`. JavaScript parsing can be checked from Linux; actual Windows rendering requires a Windows Steam session.

Desktop Adwaita relational rules for dialogs/chat and other absent contexts are suspended in-place with media groups, then restored automatically when their simple class/type/ID context appears. This preserves rule order, nesting and dynamic focus/hover rules. The previous imported-sheet disabled-flag experiment did not actually disable imports; it was not valid isolation evidence. Direct rule isolation identified the expensive inactive contexts. Live cached-page comparisons on apps 1238000 and 1771300 reduced style work from approximately 1.1–2.6 seconds to 0.14–0.24 seconds, with no network hero requests. These are local warm-cache measurements, not a cold-download guarantee. A 1,969-node, 24-property computed-style comparison found no appearance changes; the final runtime repeated this check on 1,665 nodes with no changes. A BG3 hero absent from the memory cache loaded its original 5.7 MB PNG from Steam loopback in 225 ms and completed its fade by 660 ms, with HTTP 200 and no broken-image error. Run `node tests/style-contexts.mjs` with desktop Steam open to verify context entry, CSS nesting/cascade, state/class changes, removal and reinsertion.
